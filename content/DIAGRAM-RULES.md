# กติกาการวาด diagram ในหลักสูตรนี้

เอกสารนี้เป็น **checklist ที่บังคับด้วยเครื่องมือ** ไม่ใช่แนวทางที่หวังว่าจะจำได้
ข้อไหนที่ `tools/check-diagrams.ts` ตรวจได้ จะทำเครื่องหมาย 🤖 ไว้ — ข้อนั้น build จะล้มถ้าผิด

> **ที่มา** — โครงคิดหลายข้อได้แรงบันดาลใจจาก
> [cathrynlavery/diagram-design](https://github.com/cathrynlavery/diagram-design) (MIT)
> โดยเฉพาะแนวคิดว่า *ต้องมี taste gate ก่อนปล่อยงาน* และ *label geometry ต้องถูกตรวจ ไม่ใช่ตรวจด้วยตา*
> เนื้อหาด้านล่างเขียนขึ้นเองให้เข้ากับข้อจำกัดของโปรเจกต์นี้ ซึ่งต่างจากของเขาตรงที่
> เราใช้ **inline SVG ที่ผูก theme token** ไม่ใช่ไฟล์ HTML เดี่ยวที่แยก light/dark เป็นคนละไฟล์

---

## 1 · สี — ห้าม hardcode เด็ดขาด 🤖

ทุกสีต้องมาจาก class ที่ผูก CSS custom property เพราะผู้อ่านเลือกธีมเองได้
สีตายตัวหนึ่งจุดทำให้ธีมใดธีมหนึ่งพังทันที

```
ถูก   <rect class="d-box-accent" .../>
ผิด   <rect fill="#F4E3D9" .../>
```

Class ที่มีให้ใช้ — `d-box` `d-box-accent` `d-box-ink` `d-bar` `d-bar-new`
`d-line` `d-line-accent` `d-arrow` `d-arrow-accent` `d-runner`
`d-label` `d-label-sm` `d-label-mono` `d-label-inv`

## 2 · ทุกอย่างต้องอยู่ใน viewBox 🤖

`rect` · `circle` · `line` · `path` ถูกตรวจแบบ exact
ส่วน `text` ตรวจได้แค่ประมาณ — ถ้าขึ้น warning **ต้องเปิดเบราว์เซอร์วัดจริง** ด้วย `getBBox()`
อย่าเชื่อ estimate อย่างเดียว เพราะมันเคยให้ false positive มาแล้ว

## 3 · ทุก figure ต้องมี caption และเลขต้องไม่ซ้ำ 🤖

รูปแบบ `<b>Figure N</b> · คำอธิบาย` — **label ในรูปและ caption เป็นภาษาอังกฤษ**
ส่วนคำอธิบายใต้รูปเป็นไทยได้ · โมดูลที่มีส่วน "ที่มา" ใช้ `Figure 0` สำหรับ timeline

## 4 · Accessibility 🤖

`<svg>` ทุกตัวต้องมี `role="img"` และ `aria-label` ที่บอกว่ารูปสื่ออะไร
ไม่ใช่แค่ชื่อรูป — คนที่ใช้ screen reader ต้องได้ใจความเดียวกับคนที่เห็นรูป

## 5 · Diagram ต้องสื่อสิ่งที่เป็นจริง

ข้อนี้เครื่องตรวจไม่ได้ และเป็นข้อที่เคยพลาดจริง

- **ความยาวแท่งต้องเรียงตามค่าที่มันแทน** — เคยวาดแถบ "ความเสี่ยง" ที่ `acceptEdits` ยาวกว่า `bypass` ซึ่งกลับหัวกลับหาง
- **แท่งต้องอยู่ในคอลัมน์ของตัวเอง** ถ้าเป็นการเทียบรายคอลัมน์
- **ปลายลูกศรต้องไม่ทับกล่องที่มันชี้** — เว้นอย่างน้อย 4px
- **ตัวเลขในรูปต้องตรงกับตัวเลขในเนื้อหา** ถ้าเนื้อหาบอก 6 เท่า รูปต้องแสดง 6 เท่า

## 6 · งบความซับซ้อนต่อรูป

รูปหนึ่งเล่าเรื่องเดียว ถ้าต้องอธิบายเกินหนึ่งประโยคว่ารูปนี้บอกอะไร ให้แยกเป็นสองรูป

แนวทางคร่าว ๆ — กล่องไม่เกิน ~12 · เส้นเชื่อมไม่เกิน ~10 · ระดับชั้นไม่เกิน 3

## 7 · Animation

ใช้เมื่อมันสื่อ *การเคลื่อนที่* จริง ๆ เท่านั้น (ลูป · ทิศทางการไหล)
ต้องมี `@media (prefers-reduced-motion: reduce)` ปิดให้เสมอ — มีอยู่แล้วใน `assets/style.css`

## 8 · ก่อนปล่อย

```bash
bun run check:diagrams      # 🤖 exact checks + warnings
bun run build:site          # จะรัน check ให้อัตโนมัติ และล้มถ้าไม่ผ่าน
```

แล้ว **เปิดหน้าจริงในเบราว์เซอร์** วัดด้วย `getBBox()` ถ้ามี warning ค้างอยู่
