§01

The 8 gaps this course fills

None of these were added because they were nice to have. Each one is where a workflow breaks once a team depends on it — ordered by the damage of skipping it.

G1

Evals — measuring your own agent system

M12 · 9 lessons →
The largest gap. If you cannot measure, you are tuning prompts on feeling. LLM variance is wide enough that "it felt better" is pure noise.
G2

Security and the agent threat model

M13 · 9 lessons →
A coding agent has a threat model unlike a web app's, and an installed skill is code running with your privileges.
G3

Context engineering

M02 · 9 lessons →
The clearest dividing line between people who use agents well and people who don't — and it pays back more than changing models.
G4

Brownfield and legacy

M08 · 7 lessons →
Labs that start from an empty folder teach work almost nobody does. Real work is a six-year-old codebase with no tests.
G5

Token and model economics

M03 · 8 lessons →
Cost decides whether a workflow survives a team of twenty or only works for you alone.
G6

An agent-ready codebase

M05 · 8 lessons →
Repo structure pays back permanently; a better prompt pays back once.
G7

Multi-agent orchestration

M10 · 8 lessons →
Multi-agent is an architecture, not a feature — and the most important lesson is when it loses to a single agent.
G8

Governance and real team adoption

M15 · 9 lessons →
Most courses end at "you can use an agent now". The real problems start when fifteen people use one at once.
