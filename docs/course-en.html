PHASE 00 Foundations — understand the mechanism, don't memorise commands M01–M03 · 25 lessons · 8h
M01 8 lessons
2.5 h

How an agent actually works

See that an agent is an ordinary loop wrapped in engineering, so you can debug it when it misbehaves

  1. What the agentic loop really is, and why that is enough
  2. Anatomy of a harness — system prompt, tool registry, context assembler, permission layer, result renderer
  3. The tool-use protocol — parallel calls, error results, and why every result must come back in one message
  4. Every stop reason, and how to handle each one
  5. Thinking and effort — how depth changes tool-call behaviour, not just quality
  6. The permission model, and why "allow everything" is security debt
  7. Seven ways agents fail, and which layer fixes each
  8. LABwrite a ~150-line mini-harness — loop, three tools, permission gate
OutcomeYou can name which layer of the harness a strange behaviour came from
M02 9 lessons
3 h EXPANDED G3

Context engineering

Treat context as a budget to manage, not a bucket to fill until it overflows

  1. The context window is a budget, not storage — a million tokens still needs managing
  2. Four rules for what belongs in context — relevant, fresh, cheaply rendered, re-findable
  3. Attention dilution — why quality drops before the window is full
  4. The memory hierarchy, and what belongs at each level
  5. Writing a project memory file that earns its keep
  6. Three mechanisms people confuse — compaction, context editing, and an external memory
  7. Sub-agents as a context barrier, not just parallelism
  8. Retrieval or stuffing — when to attach and when to let it search
  9. LABcut 40% of context and measure whether quality moves
Outcome30–60% lower cost per task at equal or better quality
M03 8 lessons
2.5 h EXPANDED G5

Token and model economics

Decide about cost with arithmetic instead of a feeling that a model is expensive

  1. The four token columns — input, output, cache write, cache read
  2. Prompt caching in depth — prefix matching and render order
  3. Silent cache killers, and a five-minute audit that finds them
  4. Routing models by economics — which work repays which tier
  5. Cost per completed task, not per request
  6. Effort before model — the lever to pull first, and the cache trap in cascades
  7. Batch, task budgets, and ceilings the agent can actually see
  8. LABprofile a week of real work and find three levers
OutcomeYou can say which model and effort level a task deserves, with data behind it

Multi-agent orchestration

Use several agents where it genuinely wins, and recognise when it loses to one

  3. Pattern 2 — pipeline: every stage with a structured contract
